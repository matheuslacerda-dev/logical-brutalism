# 05 :: 访问性审计和零信任清单 (ACCESSIBILITY AUDIT)

可访问性不是“特性 (feature)”。这是对公理 I 盲目顺从的表现。不妥协。

## 色彩对比度定理 (THE CONTRAST THEOREM)
任何字体都不能面临褪色或晕染风险。遵守 AAA 基点是数学强制措施，不是色彩感性的自我感动：
1. 主活动颜色 (`--color-amber`: `#FFB000`) 与 底板 (`--color-void`: `#0A0A0A`) 的对比比率必须为数学测算出来的 **10.81:1**，远超出 WCAG 规定的 7.0:1 的刚需 AAA 水平。

## 盲测零偏离定律 (THE "BLIND TEST" RULE)
终极判定机制：如果在开发环境中的 `:root` 添加 `filter: grayscale(100%);` (全灰度去色) 时，系统不可因此导致结构解析降级。完全纯靠结构 Y 轴拉扯的间距控制。

## 零信任审查清单 (ZERO-TRUST CHECKLIST)
所有递交 `master/main` 代码池的数据必须回答，`FALSE` 的响应会触发自动封禁：
* `[ ]` 调色配置是否绝对不包含非 `Global Tokens` 定义色？
* `[ ]` `--color-amber` 是否处于绝对的霸权地位且没有战术层面的并发竞态色？
* `[ ]` 所有触控模块在数学度量下的高度都不小于 `44px`？
* `[ ]` Aria HTML 节点树是否完全涵盖在被激活状态中以符合语义上的受限强制调用环境？
